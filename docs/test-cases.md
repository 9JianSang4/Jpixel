# Jpixel 测试用例库

> 这不是“每次都要全跑”的清单，而是分层测试库。
> `docs/spike-test-plan.md` 是 **T0：spike 最小验收集**；本文是 **T1–T3：产品级测试库**。

## 0. 分层执行策略

| 层级 | 用途 | 规模 | 什么时候跑 |
|---|---|---|---|
| **T0 Spike 验收** | 决定 B+ 架构是否可行 | 约 27 个（现有 spike 计划） | 现在，一次性 |
| **T1 冒烟** | 每次构建确认没坏 | 12–15 个 P0 | 每个开发构建 |
| **T2 发布门禁** | v1 发布前完整回归 | 60–70 个 P0+P1 | 每个 release candidate |
| **T3 深度/探索** | 边缘环境、长稳、兼容性 | 30–40 个 P1+P2 | 发布前择机 / 大版本 |

优先级定义：

- **P0**：核心功能，坏了不能发布；
- **P1**：重要体验/稳定性，发布前应通过；
- **P2**：边缘场景/兼容性，记录问题即可。

自动化标记：**A** 自动化、**M** 手动、**A+M** 两者都有。

4. G01/G03/G05
5. R01/R02/R05
