# Jpixel Spike：原生截图遮罩技术验证（测试计划）

- 版本：v0.1（待确认）
- 状态：测试计划，不是最终产品规格
- 关联决策：B+ 架构 —— Rust 核心 + 原生截图遮罩 + 原生贴图窗口 + Tauri/Vue 设置窗口（按需创建）
- 目标：在 Windows 11、双屏混合 DPI 下，验证原生遮罩能否满足“快、准、省内存”。

> 说明：spike 代码是一次性实验，不是最终产品代码；它的产出是测试数据和 go/no-go 结论。

---

## 1. 目的

回答四个问题：

1. 原生遮罩能否在 1920×1200@125% + 1920×1080@100% 的双屏上**像素级对齐**？
2. 按 F1 后，遮罩能否在 **100ms 内**出现（p95）？
3. 选区确认到剪贴板能否在 **60ms 内**完成（p95）？
4. 空闲/峰值内存是否可控（空闲 ≤40MB，单次 1920×1200 峰值 ≤150MB）？

---

## 2. 范围

### 2.1 做

- 全局热键 F1
- 前台窗口 → 目标显示器
- DXGI 抓取单块屏幕
- 原生无边框置顶窗口（不进任务栏）
- 冻结画面 + 暗色遮罩 + 选区矩形
- Enter 复制选区到剪贴板
- Esc 取消并恢复焦点
- 内置计时、内存日志、剪贴板像素回读校验
- `--bench` 自动跑 10/20 次并输出 CSV

### 2.2 不做

- 设置页、托盘、配置、开机自启、单实例
- 贴图窗口
- 画笔、橡皮、撤销
- 工具栏、放大镜、取色
- 保存对话框、安装包、签名、自动更新
- 跨屏框选
- RDP / HDR / 真实 4K 抓取（4K 只做后续验证）

## 3. 测试环境

| 项 | 值 |
|---|---|
| 操作系统 | Windows 11（请记录 `winver` 的版本号，例如 23H2 / 24H2） |
| 显示器 A | 1920×1200，缩放 125%，当前为主屏 |

> **抓屏修复**：副屏黑边 / C1 `Area size is invalid` 已修正（`capture_area` 的 x/y 是本地坐标且会二次乘 scale_factor）。请重新跑 C1/C3/C4，并特别检查副屏四周是否还有黑边。

>
> ```
> Monitor 1: 1920x1200 @125% rect=(0,0,1920,1200) primary
> Monitor 2: 1920x1080 @100% rect=(1920,0,1920,1080)
> ```
>
> 编号以 spike 打印为准；排列变化后编号可能变化。

## 4. 测试配置

A = 1920×1200 @125%；B = 1920×1080 @100%。

| 配置 | A（125%）位置 | B（100%）位置 | 主屏 | 目的 |
|---|---|---|---|---|
| C1 | 左 | 右 | A | 125% 主屏，正坐标 |
| C2 | 右 | 左 | B | 100% 主屏，主屏切换 |
| C3 | 右 | 左 | A | B 在负 X 坐标 |
| C4 | 下 | 上 | A | B 在负 Y 坐标 |

设置方法：

1. 右键桌面 → 显示设置；
2. 在“选择并重新排列显示器”里拖动屏幕，改变左右/上下；
3. 选中目标屏，勾选“设为主显示器”；
4. 确认分辨率和缩放（A 125%，B 100%）；
5. 每个配置截图保存为 `display-C1.png` … `display-C4.png`。

> 测试结束后，记得把排列和主屏恢复成你习惯的设置。

## 5. 测试用例

### 5.1 布局与 DPI（核心必测）

公共预期：遮罩只出现在目标屏；覆盖整屏（含任务栏）；无模糊/拉伸；另一块屏不变；Esc 后焦点回到原窗口。

| ID | 配置 | 焦点窗口在 | 预期 |
|---|---|---|---|
| D1 | C1 | A（125% 左屏） | 遮罩出现在 A，位置/尺寸正确 |
| D2 | C1 | B（100% 右屏） | 遮罩出现在 B，位置/尺寸正确 |
| D3 | C2 | B（100% 左屏，主屏） | 遮罩出现在 B |
| D4 | C2 | A（125% 右屏） | 遮罩出现在 A |
| D5 | C3 | B（100% 左屏，负 X） | 遮罩出现在 B，无偏移 |
| D6 | C3 | A（125% 右屏） | 遮罩出现在 A |
| D7 | C4 | B（100% 上屏，负 Y） | 遮罩出现在 B，无偏移 |
| D8 | C4 | A（125% 下屏） | 遮罩出现在 A |

#### D9 — 运行中改变排列

- 前置：C1 启动 spike；
- 步骤：不关闭 spike，切到 C3 排列，等 5 秒，在 B 上点击一个窗口，按 F1；
- 预期：遮罩出现在 B，位置正确（证明每次截图都会重新查询显示器，而不是缓存旧坐标）；
- 判定：Pass / Fail。

#### D10 — 125% 屏像素对齐

- 前置：C1；在 A 上全屏显示测试图；
- 步骤：把鼠标沿测试图的 10px 网格线移动，拖动选区；观察选区边框与网格线；
- 预期：边框与鼠标/网格对齐，误差 ≤1px；文字/线条不模糊；
- 判定：Pass / Fail。

### 5.2 核心功能（核心必测）

| ID | 场景 | 步骤 | 预期 |
|---|---|---|---|
| F1 | 热键启动 | 在目标屏点击记事本，按 F1 | 遮罩出现，无控制台抢焦点 |
| F2 | 框选 | 按住左键拖出一个矩形 | 暗区/选框实时跟随，不闪烁；拖动期间鼠标不能离开当前屏 |
| F3 | 复制 | 框选一块已知图案，按 Enter | 剪贴板有图；粘贴到画图后与选区一致；日志 `pixel_match=true` |
| F4 | 取消 | 按 Esc | 遮罩关闭；记事本重新获得焦点，能继续输入 |
| F5 | 重复热键 | 遮罩打开时再按 F1 | 不重复建窗，不把遮罩截进去，不崩溃 |
| F6 | 桌面焦点 | 点击桌面空白处，鼠标放在 B，按 F1 | 遮罩出现在鼠标所在屏（无前台窗口时兜底） |
| F7 | 跨屏窗口 | 把记事本拖成横跨 A/B，焦点在它上面，按 F1 | 遮罩出现在**重叠面积更大**的那块屏 |
| F8 | 任务栏覆盖 | 遮罩出现时观察任务栏 | 任务栏被遮住；Alt+Tab 里没有遮罩窗口 |

> F6、F7、F8 如果实现成本高，可以先标记 N/A，不阻塞 spike。

### 5.3 性能（核心必测）

| ID | 指标 | 方法 | 目标 |
|---|---|---|---|
| P1 | 热键 → 首帧 p95 | `spike.exe --bench --monitor 1 --iterations 10` | ≤100ms（1920×1200@125%） |
| P2 | 确认 → 剪贴板 p95 | 同上 | ≤60ms |
| P3 | 空闲内存 | 启动后不截图，读日志 `working_set_mb` | ≤40MB |
| P4 | 单次截图峰值 | `--bench` 期间记录最大 working set | ≤150MB |
| P5 | 20 次内存增长 | `--bench --iterations 20`，比较首末 working set | ≤10MB |
| P6 | 4K 参考 | 用 3840×2160 合成图做离屏渲染/裁剪（可选） | 只记录数字，不设硬线 |

> `--bench` 会按 `--monitor` 指定的显示器抓屏，不依赖当前焦点，避免控制台抢焦点影响测量。
> 对 A、B 各跑一次 `--monitor` 对应编号。
>
> spike 启动时会对每块屏做一次预热抓取。P1 记录的是**预热后的首帧**；预热耗时会在控制台单独打印，不计入 P1。P3 的 idle 行也是预热后的空闲内存。
> 开发机上的参考基线见 [spike-baseline.md](spike-baseline.md)。

### 5.4 稳定性与异常

| ID | 场景 | 预期 |
|---|---|---|
| S1 | 连续 20 次截图/取消/复制 | 不崩溃；无窗口泄漏；内存增长 ≤10MB |
| S2 | 快速连按 F1 五次 | 不崩溃；不叠加多个遮罩 |
| S3 | 连续 10 次 Esc 取消 | 每次焦点都能回到原窗口 |
| E1 | F1 被其他软件占用（可选） | 有明确错误提示，不崩溃 |
| E2 | DXGI 抓屏失败（可选） | 有明确错误提示，不崩溃 |
| E3 | 剪贴板被其他程序锁住（可选） | 重试或报错，不崩溃 |

## 6. 验收标准

### 6.1 功能

- D1–D10 全部 Pass（D10 允许 ≤1px 误差）；
- F1–F5 全部 Pass；F6–F8 至少 Pass 或明确 N/A；
- 剪贴板图像与选区逐像素一致（`max_diff ≤ 1`，alpha 全 255）。

### 6.2 性能（你的实际硬件）

- P1 ≤100ms；
- P2 ≤60ms；
- P3 ≤40MB；
- P4 ≤150MB；
- P5 ≤10MB 增长。

### 6.3 结论

- **Go**：功能/DPI 全过，性能达标，20 次稳定；
- **Conditional Go**：核心通过，但有轻微焦点/视觉问题，可在正式实现中修；
- **No-Go**：遮罩出现在错误屏、偏移 >1px、剪贴板不一致、p95 >150ms、峰值 >250MB 或崩溃；此时考虑“原生遮罩独立进程”或“全原生”作为退路。

## 7. 运行方式

1. 解压 `spike-native-overlay.zip` 到任意目录；
2. 双击 `spike.exe`（手动模式）：
   - F1：截图；
   - 拖拽：选区；
   - Enter：复制；
   - Esc：取消；
   - 控制台会打印每次的计时和内存，并写入 `spike-log.csv`；
3. 性能模式：
   ```
   spike.exe --bench --monitor 1 --iterations 10
   spike.exe --bench --monitor 2 --iterations 10
   spike.exe --bench --monitor 1 --iterations 20
   ```
4. 测试图：
   - `test-pattern-1920x1200.png` 放到 A 上全屏显示；
   - `test-pattern-1920x1080.png` 放到 B 上全屏显示。

> 启动后把控制台最小化，再点击目标窗口；避免控制台挡住截图区域。
